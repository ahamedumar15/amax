## Left open after the 5-round local review cap (round 5 majors not re-reviewed)

- Promote: no test blocks *inside* delivery's create (key claimed and row inserted, not committed) while a takeover or a same-key resume runs. The behaviour relies on core idempotency's `claimKey` waiting on the uncommitted key row, which core's own tests cover.
- Promote: no table row for the loser of the shared-project race arriving through a resumed claim (replayed project, 23505, forced release).
- Root cause of rounds 3–5 escalating: delivery's contract has no project creation yet, so promote can't create the project inside presales' transaction. When delivery publishes `createProject`, prefer a contract that accepts an external reference (opportunity id) or runs in the caller's transaction; the claim/series machinery can then shrink.
- `presales.fx_rate` has no screen or tool to add or refresh rates, and `as_of` isn't checked for staleness.
- The promote gate hard-codes delivery's `delivery:project:create` permission and finds `createProject` by an untyped lookup; take both from delivery's contract once published.
