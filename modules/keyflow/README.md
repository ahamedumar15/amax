# keyflow (change 028)

Two-way sync with Keyflow, the sister product where OKRs, check-ins, feedback and recognition live: amax sends people and teams out, and Keyflow sends goals, review scores and recognition back.

- **Owner:** `/modules/keyflow/` in `.github/CODEOWNERS`
- **Screens:** `/keyflow` (Operations; crumbs to Settings and Integrations): the connection, the open sync errors first, what went out and came in, and the latest runs. `/hr/p/:employeeNo/performance` is the person page's Performance section, mounted under hr (051): goals, review scores and recognition. Connecting and dismissing are Ask amax buttons; every card, ticket, row and list item has a pin.
- **Contracts** (`contracts.ts`), version 1: `keyflowProfile(tx, reader, personId)` (goals, review scores and recognition; null when hr's data scope hides the person; scores masked per `performance`), `lastSync(tx)` (counts only), `GOAL_STATUSES`, `RUN_STATUSES`, `PROFILE_SENSITIVE`, `EVENTS` and the payload types. A reader is a viewer or a system context core issued with `contextFor.job`; a hand-built system context fails closed.
- **Events:** `keyflow.sync.completed` and `keyflow.sync.failed`, counts and the failure only, never a person's data.
- **MCP tools** (`mcp.ts`): read `get_keyflow_sync`, `get_keyflow_sync_run`, `get_keyflow_sync_error`, `get_keyflow_profile`, `get_keyflow_record`; write `connect_keyflow`, `dismiss_keyflow_sync_error`. Search finds a person's Performance page.
- **Chat intents** (`chat.ts`): connect Keyflow.
- **The sync** is the `keyflow.sync` workflow (029), every 15 minutes. One run: plan what changed since the last send (a hash per person and team in `keyflow.link`), talk to Keyflow outside any transaction, then record the outcome as one `defineService` write (`keyflow.sync.record`), audited by count. Leavers go out once more as `left`. Each record from Keyflow is untrusted and checked on its own: a bad one is an `invalid` error, one for a person amax doesn't know is `unmatched`, and a person Keyflow refuses is `refused`. An error that recurs bumps its run count instead of opening a new row; a refused person Keyflow later accepts closes their error. A failure to reach Keyflow is a failed run with its reason on the screen.
- **Keyflow over the wire** (`server/http.ts`): `POST v1/sync/directory` (`{ people, teams }` → `{ refused }`) and `POST v1/sync/changes` (`{ cursor }` → `{ goals, reviews, recognition, cursor }`), JSON, `Authorization: Bearer <key>`. Only a public https endpoint, through the 035 egress guards in `@amax/api/egress` (the connection pinned to the checked address, no redirects), with a 10 MB cap and a 60 s timeout. The key is the 031 `keyflow` credential, opened with `useSecret` only for the call. A new endpoint sends everyone again and pulls everything again.
- **Sandbox Keyflow** (`server/sandbox.ts`): the demo tenant's connection is `sandbox`, a built-in fictional Keyflow, so demo data never calls a real endpoint. It refuses anyone who hasn't started yet and answers once with the demo goals, scores and recognition, including one goal for a Keyflow person amax doesn't know.
- **Who sees what:** the sync screen needs `keyflow:read` (Admin, IT Admin, HR); connecting and dismissing need `keyflow:manage` (Admin, IT Admin). A person's Keyflow data needs `keyflow:profile` (HR, Leadership and PM for anyone hr's data scope reaches; everyone else `@own`). Review scores are `performance` (002): HR, Leadership, the person and their manager.
- **Depends on:** hr (people, departments as teams, managers, the data scope). Integrates with nothing optional.
- **Data:** `keyflow.connection`, `keyflow.sync_run`, `keyflow.sync_error`, `keyflow.link`, `keyflow.goal`, `keyflow.review_score`, `keyflow.recognition` (RLS on `tenant_id`); retention entries in `module.ts` (`keyflow.link` holds only pseudonymous ids and hashes).
- **Not here yet:** a Performance tab on hr's person page is one line in hr (a separate hr change; this module touches nothing outside its folder). Keyflow's real API isn't published yet: the wire shape above is this module's contract with it, version 1.
- **Tests:** `pnpm --filter @amax/keyflow test` (DB tests need `DATABASE_MIGRATE_URL`; Keyflow is always a fake transport); screen e2e: `pnpm --filter @amax/keyflow e2e` after `pnpm --filter @amax/web build`.
