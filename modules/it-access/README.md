# it-access (change 021)

What each person can use (Entra groups and admin roles, Microsoft 365, Azure DevOps, GitHub and SaaS seats, Intune devices), licence spend, and the access changes IT approves.

- **Owner:** `/modules/it-access/` in `.github/CODEOWNERS`
- **Screen:** `/it-access`, for IT Admin and Admin. The four stats lead (licence spend, unused seats, devices compliant, leavers with access), then Licences (the products with unused seats, and the total), spend by product, the licence agent's savings and Devices, then People and access, attention first (admin roles, contractors, leavers), with a read-only filter (`?people=admins|leavers|contractors`, looked up in a fixed list and encoded) and "Show all" (`?all=1`). "Start access review", "Add licence", Review, Extend and Open ask chat ("Ask amax"). Every tile, row, card, list item and legend row is pinned; there are no forms.
- **Prices (055):** licence prices are the `pricing` class. Admin sees them; IT Admin gets seats and use, and every read tool leaves money fields out for them. Suggestion titles and details never carry a price.
- **Records:** `it_access.product`, `account` (a person in hr, or a named contractor with an expiry), `seat`, `device`, `change` (an approved change, queued for its day), `sync_run` and `write_consent`.
- **Sync (AC-1):** the `it-access.sync` workflow (hourly) reads Microsoft Graph (licences from `subscribedSkus`, Entra sign-ins and directory roles, Intune devices), Azure DevOps (the user entitlement summary) and GitHub (Copilot seats). Each source opens only its own 031 read credential: `msgraph-read` (JSON `{ tenant, clientId, clientSecret }`), `azure-devops` and `github` (JSON `{ org, token }`). A source without a credential is recorded as skipped. Reads go to fixed hosts only (Graph token requests through `@amax/api/egress`).
- **Write registration (AC-1):** a separate app registration in `msgraph-write`, used only by the `it-access.apply` workflow to make approved changes. It is off by default; an Admin consents per tenant with `set_access_write_consent`, naming the scopes (`LicenseAssignment.ReadWrite.All`, `User.RevokeSessions.All`, `GroupMember.ReadWrite.All`). IT Admin can't consent. While it is off, or a scope is missing, or the product isn't managed through Graph, an approved change is marked `manual` with what IT must do by hand.
- **Changes (AC-2):** grant, revoke and remove seats are 006 suggestion kinds (`it-access.grant`, `it-access.revoke`, `it-access.remove-seats`), `sensitive` and with undo, that only `it-access:change:approve` (IT Admin, Admin) can accept. Agents and people only propose: `request_access_change` makes a suggestion acting for the person who asked, so someone else approves it. Accepting queues the change for its day; undo cancels it, or queues the inverse once it was made.
- **Licence agent (AC-2):** after each sync, proposes removing a product's seats once five or more had no use for 60 days (or an add-on was never used).
- **Leavers (AC-3):** `hr.person.left` proposes revoking all of the person's access (sign-in sessions, licences, groups, admin roles) on their last day; the change waits for the day. With onboarding installed, `onboarding.access.requested` makes the same revoke (deduplicated) or a Microsoft 365 E3 grant for a joiner.
- **Contracts** (`contracts.ts`): `ACTIONS`, `READ_CONNECTORS`, `WRITE_CONNECTOR`, `WRITE_SCOPES`, `accessOf(tx, reader, personId)` (a person's counts, admin roles and last review), `reviewStatus(tx, reader, since)` (for 036's access-review evidence), `EVENTS` and payload types. Neither read returns money.
- **Events:** `it-access.sync.completed`, `it-access.change.queued`, `it-access.change.applied`, `it-access.review.recorded`, `it-access.consent.changed`. Handles its own `sync.completed` (licence agent), hr's `hr.person.left` and onboarding's `onboarding.access.requested`.
- **Permissions:** IT Admin: read, request and approve changes, record reviews and extend contractors. Admin holds every permission, and alone can consent to the write registration.
- **Depends on** hr (011), agents (006) and secrets (031). **Integrates with** onboarding (013): without it, the leaver path still runs from hr.
- **Fixtures:** fixtures.md's 12 products ($14,860 a month; 23 unused seats, $624 a month), an account for everyone in hr (leavers with everything revoked), the DataCo contractor (fictional, expires Nov 15) and 231 devices. Seat use dates are relative to today. A seeded sync event makes the licence agent's two savings (Figma and Test Plans) on the next job tick.
- **Tests:** `pnpm --filter @amax/it-access test` (DB tests need `DATABASE_MIGRATE_URL`); screen: `pnpm --filter @amax/web build && pnpm --filter @amax/it-access e2e`.
