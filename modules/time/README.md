# time (change 009)

Timesheets: hours logged by people and by agents against delivery projects, ISO weeks submitted for approval, approved through the manager or project chain, and locked once approved.

- **Owner:** `/modules/time/` in `.github/CODEOWNERS`
- **Screens:** `/time` and `/time/w/:week` (Team time), `/time/my` and `/time/my/:week` (My timesheet). Weeks are ISO keys such as `2026-W42`.
- **Contracts** (`contracts.ts`): `weekTotals(tx, viewer, week)` and `projectHours(tx, viewer, range)`, which apply the caller's data scope (own time, plus weeks they could see on Team time; `projectHours` returns aggregates only), ISO week helpers (`isoWeekOf`, `weekStart`, `workDays`, `shiftWeek`, `weekKey`, `parseWeekKey`), `EVENTS`, `WEEK_STATUSES` and the event payload types. Version 1.
- **Events:** `time.entry.logged`, `time.entry.corrected`, `time.entry.deleted` (each carries the entry's `revision`, so a consumer keeps only the newest; 070), `time.week.submitted`, `time.week.approved`, `time.week.rejected`, `time.week.reopened`, `time.week.reminded` (notification rules for submitted, approved, rejected and reminded weeks live in `module.ts`; 030 delivers them).
- **MCP tools** (`mcp.ts`): read `get_team_week`, `get_my_week`; write `log_time`, `correct_time_entry`, `delete_time_entry`, `submit_week`, `approve_week`, `reject_week`, `remind_week`, `reopen_week`. Time logged over MCP is agent time.
- **Chat intents** (`chat.ts`): log time, fix hours, remove hours. `get_my_week` and `get_timesheet` list the week's entries by id (an Admin sees them on others' weeks too), so chat names the exact entry.
- **Logging:** a day is required (YYYY-MM-DD in the person's calendar; the server doesn't guess "today" in UTC) and must be Monday to Friday; a day holds at most 24 h, in steps of 0.05 h. A submitted week can't change until the approver sends it back.
- **Corrections (070):** an entry's hours, billable flag, note or project can be fixed, or the entry deleted, by its owner in a draft or rejected week; the day never changes (delete and log again). An approved week's entries change only by another Admin, audited as `time.week.locked_change`. Undoing a commit-draft suggestion deletes its entry the same way, with the event.
- **Weeks in writes:** submitting, approving, rejecting, reminding and reopening name the week (or a `weekId`); the server never picks one by its clock. A week you can't act on and a missing one give the same error, and nothing is locked before that check. Read tools still default to the latest week.
- **Approval rules:** you never approve your own week. Admin approves any week; a manager approves the weeks of their reports (`viewer.reports`, filled by hr when it's installed); a project manager approves weeks with time on a project they manage. Reject needs a comment. Approved weeks are locked: changing one needs another Admin (never on your own week), is audited as `time.week.locked_change`, and `reopen_week` takes a reason and, like approving, is never done on your own week.
- **Depends on:** delivery (projects, managed-project scope). **Integrates with:** hr (reporting lines; without it only the project chain applies), leave (not wired yet; until it is, a week carries a free-text note such as "Casual leave Fri").
- **Allocated hours** on the screen are 40 h per person until allocations (010) publishes capacity.
- **Data:** `time.entry` (with `revision`), `time.week`, `time.approval` (RLS on `tenant_id`); retention entries in `module.ts`.
- **Tests:** `pnpm --filter @amax/time test` (DB tests need `DATABASE_MIGRATE_URL`); screen e2e: `pnpm --filter @amax/time e2e` after `pnpm --filter @amax/web build`.
